# 降级流程（缺信息 / 无地区价格 / 临时变更 / 输出失败时怎么办）

> 原则：能降级就降级，**不猜、不伪造、不中断**；每次降级都在输出中告诉用户降了什么。

## 缺用户信息

- 必填项（基本情况/避开情况/吃饭做饭/菜系口味/预算）有缺项 → 动态追问（`references/questionnaire.md`），只问缺失且影响计划的项；未指定计划日期时按 request_date+1 连续 7 天；未选输出格式时默认 Markdown；做法为问卷必选项，漏选只补问这一项，不设默认
- 用户不答非必填项 → 用默认值继续：活动量=轻、模式=按周期默认、口味=家常清淡、库存=油盐蛋
- 女性用户未提供周期信息 → 不启用周期切换，按单一模式（用户选或默认平衡激素）跑一周，提示"提供周期信息后可切换"

## 价格数据缺失（默认情况）

采购不再使用平台接口；只有所在地公开市场价。

→ `workflows/procurement-flow.md` 第 2 节：采购清单（食材/购买量/规格/参考价/平替/剩余去向）。这是**常态而非异常**。

## 无城市价格适配器

- 有 `references/cities/<城市>.yaml` 但数据取不到 → 只输出采购清单与规格，加一行"部分食材暂无可靠参考价，未计入预算总额"
- 连 yaml 都没有 → 同上；并按样板提示可为该城市新建适配器
- 禁止虚构总价；有可靠价格的食材照常逐项列出具体参考价；无可靠价格的食材不加金额，只加一行"部分食材暂无可靠参考价，未计入预算总额"；任何情况下不出现"实价为准"类字样

## 菜谱库无匹配

- `data/recipe-index.json` 过滤后候选不足 → 依次放宽：①烹饪时间上限 +10 分钟；②味型要求放宽；③用 `references/recipe-pool.md` 的一锅出模板直接组装（篮子食材+常备调味）；④用户常吃菜走 transient_user_recipe 通道（十项检查，仅限当前计划）
- 放宽到哪一级，在计划里如实说明

## 用户临时变更

- 聚餐/外食插入 → 该餐按外食点餐规则处理，当天标"预计接近目标"
- 某食材没买到 → 用该食材的 substitutes 替换，重算该餐营养
- 某顿没吃/吃多了 → 按"执行偏差处理"（不惩罚、不补偿、次日恢复）

## 安全相关永不降级

- 慢病/用药/孕产/未成年/进食障碍史 → 只有"医嘱范围内适配"一条路，不存在降级绕过
- L0/L1 禁食上限、>24h 禁食不生成 —— 任何情况下不放宽
