# 月食（yueshi）术语表

本文件只收录领域术语的准确定义，不含实现细节（实现与历史见 `CHANGELOG.md`、`docs/adr/`）。

## 商品语义判定

- **商品语义判定**：对查价候选商品名执行"身份 → 结构 → 加工 → 附加属性"四维门禁，输出三态决策的判定过程。技能仓与叮咚查价助手共用同一套判定语义。
- **判定档案（acceptance_profile）**：一个概念的验收条件集合（所需品类、物种、部位、可接受结构、排除加工、特定要求），是判定器的输入；来自 `data/product-acceptance-profiles.json`，由查价清单随项携带。
- **概念档案（concept profile）**：一个概念的完整描述 = 显示名 + 召回范围 + 判定档案 + 不确定策略。判定档案是它的一个组成部分。
- **四维证据**：判定器输出的统一证据结构——identity（身份）/ composition（结构）/ processing（加工）/ attribute_evidence（附加属性证据）；不足的证据标记为 unknown，不臆测。
- **三态决策**：accepted（接受）/ rejected（拒绝）/ review_required（证据不足需人工查看）。证据不足一律 review_required，不得自动进入正式采购建议。
- **证据层级（evidence_level）**：附加属性证据的分级；`title_claim` 表示仅商品标题声明（如"全麦"），不是配料表验证结论——透传给用户时须附"购买时请查看配料表确认"。
- **风味声明守卫**：紧跟「味」字的属性词（如「全麦味」）是风味描述而非原料证据，不得当作属性证据命中。
- **物种误伤守卫**：物种词命中时排除非物种上下文（如"牛奶/奶油/牛油果"中的"牛"不构成牛肉冲突）。
- **死状态**：目录规则中登记、但形态词典不存在的形态名（如 processed/prepared）。判定器两侧一致地不命中；属待清理的历史遗留，不代表行为差异。

## 形态与目录

- **形态（form）**：商品标题可识别出的切配/部位/加工/保鲜状态（如 diced、whole_leg、marinated、frozen_raw）。
- **形态词典**：形态名 → 关键词 + 是否限制性的全局词典（`data/product-form-dictionary.json`），技能仓与助手共用。
- **限制性形态**：命中后受用途约束的形态——查询项设 allowed_forms 时，识别出且不在允许清单内即拒绝。
- **否定前缀守卫**：命中位置前两字符内带 免/无/不含/未/去 时不计命中，只作用于加工状态形态。
- **整块守卫**：「块」前一字为「整」时归 whole，不归 cut_pieces。
- **目录规则（query_profile）**：食材目录中每个食材的查询与匹配规则（精确词、别名、允许形态、排除形态、硬排除词等）；助手精简清单缺字段时由语义快照展开。
- **条件接受（conditional_accept）**：本体合格但附独立调味包的商品——接受候选并生成"附独立{包}，可不用"购买备注；本体已调味仍按 marinated 拒绝。

## 单一来源与快照

- **词汇契约**：商品语义判定全部词表（物种词、品类词、无添加糖词、全麦词、加工状态形态集等）的唯一数据来源（`data/commodity-vocabulary.json`）；两侧判定器代码不持有词表。
- **语义快照（semantics-snapshot）**：由导出脚本从词汇契约、形态词典、目录规则生成、随助手内嵌分发的单一数据文件；禁止手改。
- **行为对拍（behavior parity）**：同一组边界商品名在技能侧与助手侧跑同一判定并断言结果一致——取代"读对方源码文本"的同步探针。

## 流程与门禁

- **查价清单**：技能仓交给用户的唯一正式输入清单（`月食-查价清单.json`），逐项携带概念档案。
- **价格结果**：助手回传的唯一正式结果文件（`月食-叮咚价格结果.json`），候选带三态判定与四维证据。
- **采购选择层**：只从 accepted 候选中生成最终采购建议；无 accepted 时回退参考估价。
- **菜谱库发布门禁（release gate）**：菜谱库构建链最后一环——审计、覆写、产物哈希全部通过才允许生产库被读取；目录或 taxonomy 变更后必须重跑完整构建链。
- **人工覆写（review override）**：人工对分类结果的单点修正，带原因与绑定哈希；所绑定的菜谱/分类规则/目录任一变化即 stale 并阻断发布，须重新审核。
