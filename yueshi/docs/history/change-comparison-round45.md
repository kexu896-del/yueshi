# round45 变更对照（实跑反馈：口径修正 + 生成提速）

依据：《月食改动0825.docx》。成品 8.5/10；慢点定位"模型人工式试错调克数"。

## 成品口径修正（4 项扣分点）

| 问题 | 落实 |
|---|---|
| 男方周一 151g vs 页面 ≤150g | 采用意见推荐方案 A：nutrition-routing 新增「营养显示取整口径」——未舍入值超上限 ≤0.9g 记 rounding tolerance 视为达标；可见目标写"约"区间 + "个别日期因食材取整允许约 1g 浮动"说明；禁止内部通过但页面看似超标（t05a–c） |
| 大米约 2.5kg 生熟口径 | 渲染硬门禁：米类采购项必须生米（raw）汇总 + 双行标注"生米约 Xg（对应熟米饭约 Yg）"；缺生米口径或缺熟饭对应量均渲染失败（t03 正/负/正三用例）；runtime-rules 同步"禁止以熟饭重充当生米" |
| "无人在家吃饭，三餐自行解决" | 标准文案定为"今天不在家用餐，本计划不安排菜单，也不计入本周采购与营养合计"（output-policy）；两句旧表述进渲染 BANNED 清单（t04） |
| 带鱼 500g 包装浪费过半 | runtime-rules 新增包装消耗优先级四级（小包装→散装→本周两餐→续存下周写明去向；剩余超半包须复核小包装/散装）（t05d） |

## 生成提速（意见§四全部落实）

| 优化 | 落实 |
|---|---|
| 局部重装配模式 | change_scope=schedule_and_ingredient_patch：仅日程/排除食材变化时走 7 步局部管线（篮子过滤→重装配→联合求解→批量校验→采购汇总→备餐派生→渲染），跳过安全重采/目标重算/预算库存重问/完整预选（t06a/b） |
| 试克数 → 一次联合求解 | 新脚本 household_portion_solver.py：scipy linprog(HiGHS)，变量=各成员可调整食材克数，约束=热量上下限/碳水上限/蛋白下限/脂肪范围/克数范围，目标=L1 最小改动（靠近原菜单、少改食材）；locked 食材计常量；infeasible 退出码 3 交模型局部换菜（t01/t02） |
| 先求解再统一渲染 | 装配→求解一次→采购聚合→全门禁→冻结→只渲染一次；仅排版问题允许重渲染（t06d） |
| 不变数据缓存 | 成员目标/库存/预算/价格/菜谱索引/营养表/换算表按哈希复用（t06e） |
