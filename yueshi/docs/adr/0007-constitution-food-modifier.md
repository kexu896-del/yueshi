# ADR-0007：体质食养的显式自述软偏置（round79）

- 状态：已接受
- 日期：2026-09-21

## 背景

技能与倪海厦资料融合后保留了中医风格速查（`references/tcm-food-style.md` 九分法）与可选功法模块，
但政策明确"中医食养不进入生成链路、不做体质诊断"，因此即使用户主动说出自己的体质（如"阳虚、怕冷"），
系统也不会调整任何食材——只能通过"想吃温热"等五项生活化偏好转为烹法与味型，温补食材不会进入篮子。

用户诉求：**问卷不能变繁琐**（用户可能不具备中医知识）、**只在明确自述时**按体质做食材与菜谱调整，
且调整必须真实作用于篮子与具体温补食材，而不是只改烹法。

## 决策

1. **显式自述、不设问卷**：不新增体质问题、不做量表、不推断；仅当用户主动说明体质或体感
   （怕冷/手脚凉/湿气重/口苦/容易瘀青/贫血等）时，登记 `constitution_context`（`declared` 体质键 +
   `rules_version` + `applied`）。未自述 → 零影响。
2. **数据来源（可追溯）**：
   - 体质定义：ZYYXH/T157-2009 九种体质（标准）+ 教材补充血虚、阳盛（中医营养学 2012 第九章）；
     共 11 种，自述别名覆盖"怕冷/湿气重/口苦/贫血/容易上火"等生活化说法；
   - 食养规则：`data/constitution-food-rules.json`（宜/忌食材、性味方向、烹法、注意事项，中性转写；
     食材清单取中医营养学 2012 与中医食疗学 2021 的并集，来源逐条标注）；
   - 性味归经：`data/food-nature.json` v1.2.0（以中医营养学 2012 为主源、中医饮食营养学 1992 兜底；
     `items` 84 项教材条目；`inferred` 21 项类别级推断——basis=category_inference、权重 0.5、
     不覆盖教材（同名冲突校验失败）、不冒充原文）；
   - 安全边界：`data/medicine-food-catalog.json`（药食同源目录 106 种，2002/2019/2023/2024 四批）。
3. **软偏置，真实作用于篮子**：`ingredient_preselector.py --constitution` 在 P/V/C 槽位内给相宜食材
   加分、禁忌食材减分；`recipe_ranker.py --constitution` 在菜谱同分裁决时优先相宜食材/烹法。
   **不改变候选集合、槽位数量、最低菜数、营养计算与任何安全门禁**；安全、过敏、医嘱、营养、预算、
   锁定篮子永远优先；特禀/过敏体质直接走安全路由，不做食养偏置。
4. **表达边界**：`constitution.user_line()` 只做生活化复述（"你提到最近怕冷，本周多安排了生姜、羊肉
   这类温性食材"）；不输出体质判定、辨证/证型/疗效/处方/剂量类词；渲染禁用词门禁继续生效。
5. **不启用功法**：按用户要求，`references/tcm-exercise.md` 保持可选但不进入本流程。
6. **维护流程**：新增体质/食材规则须先在数据文件登记（含来源），测试校验规则完整性与禁用语；
   性味数据只收录有出处的食材，未知不臆造。
7. **歧义与追溯（round79d）**：体质名/教材名是强别名，命中即采用；仅症状别名且同时命中多个方向
   （如"又怕冷又怕热"）时视为歧义、不启用偏置并提示用户明确方向；体质模块进入执行组件哈希；
   数据加载一律缓存，评分路径不重复读文件。

## 后果

- 用户自述体质时，篮子候选排序、平替与菜谱排序会真实偏向相宜食材（如阳虚偏温性、湿热偏清利），
  但营养达标、安全与预算不受影响；未自述时行为与之前完全一致。
- 无法识别的自述文本不猜测：打印提示并停用偏置。
- 中医知识增量以数据文件承载（可审计、可回滚），而不是把规则散落在菜谱名或渲染文案里。
- 下篇"病证食疗"未 OCR（用户明确不需要）；如未来需要病证级内容，另开议题。
