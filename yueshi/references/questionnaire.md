# 问卷（关键七项一行式 + 其余合并）

> **形式规则（固定）**：一律用**一条编号消息集中询问**，**不调用结构化问卷工具**；用户可见文案只用大白话。**不得重复询问用户已提供的信息**。引导语放在复制框外，框内只留填写区。

## 问卷模板（引导语在框外）

引导语（框外）："请按每行的示例直接改写成你的情况，一行一条；示例里已经符合你的地方照抄即可。"

```text
1. 基本情况：女，32岁，165cm，55kg，目标（减重 / 增肌 / 维持 / 健康调理）选一个，在南京
2. 要避开的情况：没有慢性病和用药；不过敏；不吃香菜
3. 周期情况（仅需要周期适配时填，否则写"不需要"）：规律，28天，上次月经8月5日开始
4. 吃饭做饭：一个人吃；工作日早餐自己做、午餐食堂、只做晚餐约30分钟；周末三餐都自己做；有炒锅和电饭煲
5. 菜系口味：中餐为主，东南亚菜 / 西餐 / 日料也可以；口味偏清淡
6. 预算：一周300元左右；类型选一个——A. 硬上限（不能超，超出要我先同意） / B. 优先目标（尽量控制在预算内，可小幅超出约5%） / C. 弹性参考（大致范围，可超出约15%）
7. 中饭晚饭要不要附做法：A. 需要，稍复杂的菜附做法 / B. 不需要，只列食材和克数
8. 输出格式：Markdown（可选 PDF / 网页 / Word；选一种就只给一种，也可多选）
9. 本周采购价格方式（逐计划周期必显选答，不跨周继承；若首轮已明确则不再重复问）：A. 使用「月食叮咚查价助手」，按叮咚当前页面商品和价格规划预算（查价结果回传后再出最终计划） / B. 不使用查价助手，按当地公开参考价格估算，直接出最终计划——**未选择记 `pending`：可展示食材预选，但不进入预选后的正式生成链路，也不静默判定为"否"**；该选项与食材预选删减在同一轮收集，不单独再追问一轮；选择只对本次计划周期有效
```

## 必填与默认值

- **必填（缺了要动态追问，最多一轮）**：基本情况（含目标与所在地区）、避开情况、吃饭做饭、菜系口味、预算。
- **餐次覆盖追问（round65 语义修正：自炊事实 ≠ 快手推断）**：吃饭做饭一行未覆盖全部三餐时（如没提早餐），必须补问该餐由谁解决，推荐问法："工作日早餐怎么安排？ A. 自己做，计入营养和采购 / B. 我在外面买，计入营养估算但不进家庭采购 / C. 只给搭配原则，不列具体采购 / D. 不吃早餐 / E. 其他"。**用户答"自己做"默认映射为 A**（planned + `preparation_location=home` + `preparation_owner=self`，计入营养与采购），**但不附带 `quick_self_prepare`、15 分钟上限或免开火假设**——是否快手需用户另行给出时间或做法条件；用户明确说"**早上只有几分钟 / 最多 10 分钟**"等**时间证据**时才叠加 `quick_self_prepare` + `max_active_minutes`；"自己简单解决 / 随便做点简单的"只记 `preparation_preference=simple`，**不得推断为快手、免开火或固定时长**（同样不得路由为 guidance_only）。只有明确"只给原则/不用安排"才走 guidance_only。用户未说明早餐可用时间时，可合并追问一句"早餐大概几分钟"，缺时间条件不得强制写入 quick_self_prepare。每日可用餐次少于3餐时，先让用户选补能方式（免煮早餐/加餐/加大正餐份量）再继续。
- **条件必填**：周期情况——仅用户需要周期适配时必填，否则视为不启用。
- **早餐快手判定规则句（round71 收口补充，语义与上文 round65 餐次覆盖追问一致）**：用户未说明早餐时间限制时，不得仅凭"自己做"或"简单解决"写入 `quick_self_prepare`；是否快手、免开火或提前备餐，须按用户明确提供的时间和做法条件单独判断。
- **必填（无默认值）**：做法选择——中饭晚饭是否附做法必须让用户选 A/B，不设默认；用户漏选时只补问这一项，不自行判断。选 B 时不读取、不生成、不渲染 recipe_steps；选 A 时只展开最终入选的 moderate/complex 中饭晚饭；早餐、简单冷食和明显无需解释的搭配不受此项影响。
- **走默认值、不进问卷**：计划日期（默认发问次日开始连续 7 天）；输出格式（默认 Markdown）。
- **逐计划周期必显选答（round58 定稿：逐周选答 ≠ 每周默认否）**：本周采购价格方式——只有用户明确选 A 才启用查价链路；不跨周继承（上周选"是"或"否"都不自动沿用），未选择记 `pending` 并随食材预选同轮收集；预选阶段只登记意愿，**唯一正式**「月食-查价清单.json」在七天菜单、做法、营养校验与最终新购需求确定后生成并交付（两阶段流程：清单交付后暂停，结果回传后再出最终版）；选 B 时全流程不生成查价清单、不出现助手引导，价格按所在地公开市场价与估算口径一次性出最终版。用户后来改变主意，可随时在对话中说"用叮咚查价"补开。
- **其余全部合并为一句**"有特别要求（常吃的菜、运动、断食经验、家中库存、聚餐等）可以一起告诉我"：不提就用默认值。
- 示例身高体重统一 165cm / 55kg；菜系选项只做简明引导（中餐/日料/西餐/东南亚菜/都可以/其他），不拆分过细。
- 已删除："主要购买方式"问题、重复的目标问题。

## 动态追问（只在缺失且影响计划时问，最多一轮）

> 食材预选属于固定工作流步骤，不计入"动态追问最多一轮"。

只问"缺失且会改变计划"的项：没给体重（算不了营养目标）、没说一人食/做饭安排（影响分层与包装）、没说预算、没说菜系口味。

**默认不询问排泄相关情况**；用户主动提到肠胃困扰时，仅转为食材风格调整，不输出体质判断。

## 一轮补问模板（四区块，round71 收口）

信息不足时合并为一轮补问，按四个区块展示；用户可以整段回复，不要求逐格填写：

```text
### 这周为谁安排
- 人数和基本情况：
- 主要目标：
- 需要避开的食物或健康限制：

### 哪些餐需要安排
- 工作日早餐：
- 工作日午餐：
- 工作日晚餐：
- 周末：

### 做饭与采购
- 厨具和单餐可用时间：
- 本周预算和已有库存：
- 是否接受提前备餐、剩余复用或免开火组合：

### 最终文件
- PDF / 网页 / Markdown / Word：
- 叮咚查价 / 公开参考价格：
```

## 条件显示（round71 收口）

- 不适用周期路线时，不显示周期问题；
- 未选择叮咚时，不显示查价助手操作；
- 单人计划不显示家庭成员配置；
- 选择公开参考价格时，不解释 JSON 回传；
- 用户没有硬预算时，只询问大致范围和可否少量超出；
- 用户已明确某项事实时，不重复询问。

## 对话暂停点（round71 收口）

每次暂停只给一个主要动作，使用固定话术：

- **食材预选后**："请回复不想要的编号；都可以就回复"都可以"。"
- **等待查价时**："请用叮咚查价助手打开这份查价清单，完成后上传价格结果。"
- **信息不足时**："还需要补充以下几项，请一次回复即可：……"

不要在同一暂停消息中解释完整内部流程、状态名称或下一阶段算法。
